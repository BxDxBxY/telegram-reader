# tgaudit — аудит Telegram-аккаунта

Скрипт проходит по вашим диалогам, собирает **структурированную базу** (SQLite)
и формирует отчёт: что оставить, что в архив, от чего отписаться. С ИИ или без —
на ваш выбор. Работает **только на чтение**: ничего не удаляет, никуда не пишет,
ни от чего не отписывается.

```
[Этап 1: метаданные всех чатов] ──► [Фильтрация явного мусора] ──► [Этап 2: логи сомнительных чатов] ──► [Этап 3: скоринг и вердикт]
```

---

## Цели проекта

Основная цель — провести аудит Telegram-аккаунта, выявить заброшенные, спамные и
дублирующие источники контента и получить прозрачный отчёт со скорингом полезности.

Чтобы не перегружать аккаунт и Telegram API, работа разделена на изолированные этапы.
Каждый можно запускать отдельно, прерывать и продолжать: прогресс лежит в БД.

### Этап 1. Первичная инвентаризация (только имена и метаданные)

Собирается полный список диалогов: ID, название, тип (`channel`, `supergroup`,
`group`, `dm`, `bot`), дата последней активности, число непрочитанных, закреплён ли
чат, в архиве ли он, выключены ли уведомления, метки Telegram (`scam`, `fake`,
`verified`).

Это самая дешёвая для API операция: один пагинированный проход, сообщения не читаются.

**Результат этапа** — отсев 40–50 % мусора чистой эвристикой, без чтения сообщений:
каналы без постов больше года, мёртвые боты, заброшенный архив. Каждый такой чат —
минус один запрос на этапе 2.

```
$ tgaudit stage1
Фильтрация по метаданным:
  кандидат на удаление без чтения        6  (27.3 %)
  оставить без анализа логов             4  (18.2 %)
  нужен срез сообщений                  12  (54.5 %)
  → этап 2 понадобится для 12 чатов из 22 (45 % отсеяно без чтения сообщений)
```

### Этап 2. Глубокий анализ по срезам сообщений (логи)

Для оставшихся чатов выгружаются **только последние 15–30 сообщений** (по умолчанию 25).
Текст обрезается до 300 символов, медиафайлы не скачиваются — никаких гигабайт переписок.

Из среза извлекается суть: тематика, язык, частота публикаций, доля рекламы,
признаки скама и инфоцыганства, доля репостов.

### Этап 3. Скоринг и категоризация

Каждый чат получает балл 0–100 и попадает в одну из корзин:

| Корзина | Что это |
| --- | --- |
| **Оставить** | активные полезные каналы, рабочие чаты, закреплённое, служебное |
| **В архив** | редко нужные материалы, справочники, дубли по теме |
| **Отписаться / удалить** | мёртвые чаты, агрессивная реклама, инфоцыганство, скам |

У каждого вердикта есть список причин на русском — видно, за что чат получил свой балл.

## Быстрый старт

```bash
git clone <этот репозиторий> && cd telegram-reader
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# посмотреть, как всё работает, вообще не трогая Telegram:
python -m tgaudit demo && cat out/report.md
```

Для работы с реальным аккаунтом:

```bash
cp .env.example .env          # вписать TG_API_ID и TG_API_HASH с my.telegram.org
python -m tgaudit login       # один раз: создаётся файл sessions/main.session
python -m tgaudit stage1      # метаданные + фильтрация (минуты)
python -m tgaudit stage2      # срезы сообщений (с безопасными паузами)
python -m tgaudit score       # баллы и корзины
python -m tgaudit report      # отчёты в out/
```

Или всё сразу: `python -m tgaudit run`.

### Команды

| Команда | Что делает | Нужна сеть |
| --- | --- | --- |
| `login` | однократная авторизация, создаёт `.session` | да |
| `stage1 [--limit N]` | инвентаризация метаданных + фильтрация | да |
| `triage [--include-dms]` | пересчитать фильтрацию по уже собранной БД | нет |
| `stage2 [--limit N] [--sample-limit N]` | срезы сообщений очереди этапа 2 | да |
| `score [--ai groq\|gemini\|none]` | баллы, корзины, (опционально) мнение ИИ | только с ИИ |
| `report [--batch-size 20]` | отчёты, таблица, батчи для ручного анализа | нет |
| `run` | все этапы подряд | да |
| `demo` | весь конвейер на синтетических данных | нет |
| `stats` | что уже лежит в базе | нет |

Этап 2 можно гонять частями: `--limit 50` сегодня, столько же завтра — очередь
детерминирована, уже собранные чаты пропускаются.

Общие флаги: `--env` (другой файл настроек), `--db`, `--out`, `--session`
(несколько аккаунтов — по отдельной сессии и базе на каждый), `-y` (не спрашивать
подтверждений), `-q` (тихий режим).

## Как не получить бан

Telegram банит не за чтение через Telethon, а за поведение, похожее на спам-бота.
Правила зашиты в код, подробности — в [docs/SAFETY.md](docs/SAFETY.md).

1. **Маскировка под обычный клиент.** `device_model`, `system_version`, `app_version`
   заполняются правдоподобными значениями (пустые поля — типичный признак скрипта).
2. **Бережный темп.** Обход строго последовательный, между чатами случайная пауза
   1.5–3.5 с, каждые 25 чатов — длинная пауза 15–40 с, на прогон действует бюджет
   (по умолчанию 150 чатов).
3. **Уважение к `FloodWaitError`.** Скрипт спит ровно столько, сколько просит Telegram
   (+2 с), и только потом повторяет. Если просят ждать дольше 10 минут — останавливается,
   сохранив прогресс.
4. **Одна сессия навсегда.** `.session` создаётся один раз командой `login`. Повторные
   авторизации по SMS-коду — прямой путь к временной заморозке.
5. **Только чтение.** Массовой автоотписки в коде нет намеренно: выход из 100 каналов
   за две минуты выглядит как угон аккаунта. Скрипт формирует список, отписываетесь
   вы сами — пачками по 20–30 в день.

## Варианты анализа

### Вариант 1. Без ИИ вообще (по умолчанию)

Чистая эвристика: даты, непрочитанные, метки Telegram, словари рекламы/скама/
инфоцыганства, поиск дублей по темам. Ничего не отправляется наружу. Правила
и пороги — в [docs/SCORING.md](docs/SCORING.md).

### Вариант 2. Бесплатный внешний ИИ

```bash
python -m tgaudit score --ai groq --ai-key gsk_...      # console.groq.com, Llama 3.3
python -m tgaudit score --ai gemini --ai-key AIza...    # aistudio.google.com, Gemini Flash
```

Чаты уходят батчами по 15 штук, между батчами пауза — лимиты бесплатных тарифов
(~30 запросов/мин у Groq, ~15 у Gemini) не нарушаются. Личные переписки наружу
**не отправляются**, пока вы явно не разрешите. Мнение ИИ пишется в отдельные поля
и не переписывает эвристику: расхождения видны в отчёте. Подробности —
[docs/AI.md](docs/AI.md).

### Вариант 3. Ручной проброс батчами

Если ключей нет и не хочется: берёте `out/batches/batch_01.md`, копируете целиком
в ChatGPT / Claude / Gemini. Промпт уже вписан в начало файла. Каждый батч —
десятки килобайт, влезает в контекст любой бесплатной модели.

## Структура базы

`data/tgaudit.db`, SQLite. Можно открывать чем угодно и писать свои запросы.

| Таблица | Содержимое |
| --- | --- |
| `dialogs` | метаданные диалогов + решение фильтрации + отметка о срезе |
| `messages` | срезы сообщений (обрезанный текст, медиа-тип, просмотры, ссылки) |
| `scores` | балл, корзина, причины, тема, язык, доля рекламы, мнение ИИ |
| `runs` | журнал запусков: что, когда, чем закончилось |

```sql
-- например: самый бесполезный контент с непрочитанными
SELECT d.title, s.score, s.bucket, d.unread_count
FROM scores s JOIN dialogs d ON d.id = s.dialog_id
WHERE s.bucket = 'unsubscribe' ORDER BY d.unread_count DESC LIMIT 20;
```

## Ограничения

- Эвристика — не истина: словари ловят типичные формулировки, но канал с рекламой
  раз в месяц может получить штраф, а тихий полезный справочник — попасть в архив.
  Поэтому у каждого вердикта есть причины, а решение остаётся за вами.
- Дубли ищутся по названиям и темам, не по содержимому: два разных канала
  про Python будут сгруппированы, хотя один может быть сильно лучше другого.
- Срез в 25 сообщений — это выборка. Штраф за рекламу масштабируется размером
  среза: по двум сообщениям приговор не выносится.
- Личные переписки по умолчанию не читаются и никогда не попадают в корзину
  «отписаться» — максимум «в архив».

## Дисклеймер

Проект предназначен для аудита **собственного** аккаунта. Использование user-API
всегда на ваш риск: даже аккуратный скрипт не даёт гарантий от ограничений
со стороны Telegram. Файлы `.env`, `*.session`, `data/` и `out/` содержат
персональные данные и исключены из git.
